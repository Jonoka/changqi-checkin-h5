# PRD · 长岐村漫游打卡

**v1.3 · 2026-09-21 · 精简范围不变**

## 1. 目标

为“印象芦苞”微信公众号提供一个免注册的照片打卡 H5。游客现场完成指定地点的照片打卡后领取小礼品；系统记录是否已领取并统计人数。

开发预算几千元、目标窗口 2–3 天，使用 Coding Agent 开发。优先完整流程、基本稳定与可恢复，不建设长期运营平台。时间是范围控制目标，不代表公众号权限、域名配置、印刷等外部步骤已经完成。

## 2. 本期做什么、不做什么

必须交付：微信直接打开地点码及公众号菜单入口与尽量静默的身份识别；活动页内扫码；一处一张现场照片；动态进度；完成后出示领取凭证；游客自己确认或扫码派发确认；已标记领取人数页；地点二维码文件；单服务器与 MySQL 部署准备。

不做：注册表单、短信、管理后台、活动编辑器、员工账号和角色、库存、订单或派发流水、多活动平台、GPS、硬件装置、线上点亮作为另一种打卡、自动/后台照片审批、公开照片墙、排行、地图导航引擎、动态码与复杂防刷、实时通知。

奖品默认足够、价值较低且线下领取。允许游客自己确认或持领取链接者确认，不以系统证明实物交付；不增加高价值奖品的核销流程。

## 4. 用户流程

### 4.1 正常打卡

公众号底部菜单 → 活动首页 → 尽量静默识别并恢复本人进度 → 点击“扫一扫打卡” → 扫描地点二维码 → 选择现场照片并预览 → 提交 → 服务器保存成功 → 更新进度。

地图或列表可查看地点，但不代替扫码进入提交流程。扫码取消、错码、照片不支持、上传失败都有明确提示和重试入口。已完成地点显示原记录，不要求重复上传。

每地点一张当前照片，允许原生拍照或相册选择；系统不自动校验真实拍摄地点、时间或内容。提交前可重选，首次上传重试不覆盖已保存照片。2026-09-24 用户确认：活动开启、尚未领取且本人已有该地点记录时，可在领取凭证和已完成地点详情显式替换单张照片，无需重新扫码；不删除/重建打卡，不改变进度、原时间或领取码。已领取或活动关闭后只读，不新增照片历史或审核状态。

### 4.2 微信直接打开地点码（2026-09-23 用户确认变更）

微信内（包括微信扫一扫或打开转发链接）打开有效 `/q/:pointKey`：校验地点 → 复用 snsapi_base 重新识别当前微信用户一次 → 固定回调建立会话并登记当前有效地点 → 进入对应地点，直接上传现场照片或查看当前已保存照片。无需先关注、返回公众号菜单或再次使用 H5 扫码；照片保存成功才增加进度。

微信外游客入口仅显示使用微信的引导，即使携带旧会话也不开放参与；显式开发演示保留。活动关闭仍可识别并查看原记录，但不登记新上传资格。地图/列表/hash 只查看、不授予新资格。页内扫一扫继续复用当前会话和 `/api/scan`。

游客说明：使用微信扫一扫现场地点二维码，打开页面并上传现场照片。也可从‘印象芦苞’公众号进入活动，使用页面内扫一扫。

不查询关注状态，不新增身份体系或授权范围。固定地点链接允许转发，不鉴别相机来源、不新增定位或防转发系统。工作人员扫游客领取码仍匿名进入派发页；人数页仍由固定凭据保护。

### 4.3 完成与领取

完成全部地点后，游客自己的 `/#claim` 按游客编号/完成状态 → 现场核查提示 → 配置顺序的各地点真实已保存照片 → 二维码/领取操作展示。工作人员当面看游客手机判断照片；不合格时提醒游客原地重拍/上传替换。每张可查看完整大图，加载失败可重试；编辑期间隐藏可出示码并禁用本页领取，上传或结果未知时不能通过返回丢失未决操作。匿名 `/r/:claimCode` 继续只作派发，不取得照片读取/修改权限。

**游客自己确认：**实际拿到礼品后点击按钮，二次确认；服务器成功后显示“已领取”和首次确认时间。

**扫码派发确认：**工作人员扫描游客的领取码，查看完成情况和领取状态，发礼后点击“已完成奖品派发”。不需要工作人员注册或登录；持该链接即可操作，是已接受的简化。

打开页面或扫描本身不算领取。两种确认共用同一个状态，再次操作不重复计人数。未完成全部地点不能首次标记领取。游客重新打开、页面恢复可见或手动刷新时恢复最新状态。

### 4.4 人数统计

负责人通过一个固定凭据保护的只读页面查看“已标记领取人数”、查询时间和刷新按钮。没有管理菜单、用户列表、编辑、图表、导出或库存。

人数是本次部署内 `claimed_at` 非空的微信身份数，不是按钮点击数、扫码次数，也不保证等于已独立核验的实物派发量。统计失败显示错误，不显示为 0。

## 5. 页面与视觉

复用已认可的绿色、米白、暖黄色文旅插画和镬耳式建筑方向，不重新设计一套风格。首页与示意地图可合并；打卡成功可用弹层。最少覆盖：首页/进度、地点上传、完成/领取、公众号引导、派发确认、只读人数。

微信内从首页、地点页或游客领取凭证分享时，聊天/群聊及朋友圈标题统一为“2026三水区芦苞镇长岐古村黄金节庆影视游园季活动”，HTML 文档 title/og:title 同步使用完整标题，不手工截断。页面内活动名称和首页 h1 仍为“长岐村漫游打卡”。分享描述保留“微信扫码参与长岐村漫游打卡，上传现场照片，集齐地点后现场领取礼品。”，沿用活动海报派生缩略图，点击后只进入公开活动首页 `https://cq.fsxinhuo.cn/`。不得分享领取码、OAuth code/state、扫码资格或当前私有/临时页面地址；内部派发页和统计页也不能成为分享目标。

已生成图片只是视觉参考，不是精确地图、实景证明或可直接上线的界面。旧图中点亮装置、固定“五点”、错误地名、未提交却显示 3/5、装饰二维码等内容，以 SPEC 为准。地点名统一使用上表，“苞榕”不得写成“苔榕”。

## 6. 数据与验收边界

用本公众号内的微信身份恢复进度，不要求昵称、头像、手机号。照片仅用于本次打卡，不公开展示；工作人员派发页不显示游客照片或 OpenID。

默认一场活动、一个用户领取一次；无库存。需要保存记录与照片，部署覆盖代码不能丢数据。照片后续清理由运营通知后人工执行，不在本期建设清理后台。

按 [SPEC.md](SPEC.md) 的 AC-01～AC-16 验收，按 [TASKS.md](TASKS.md) 执行。核心是进入、扫码、上传、恢复进度、两种领取、人数正确和常见失败可恢复；不承诺永远没有任何 bug。未做的微信真机和生产检查必须单独列出。
