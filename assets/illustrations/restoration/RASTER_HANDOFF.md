## WebCodex 本轮执行要求

### 1. 检查真实起点并导入

目标仓库 `Jonoka/changqi-checkin-h5`。编写交接时 PR #1 Draft/Open，分支 `feat/a1-wechat-scan`，head `66003bea6dc1f22260d691a3a6a5989ae8d71113`；这个值是素材接入前基准，不是固定开发起点。

先读 AGENTS、README、SPEC、TASKS、DEPLOY、本说明、recipe.json 和 prepare-a4-art.mjs。核对最新 main、PR #1 状态/head/Review、其他开放 PR、本地分支/HEAD，以及 `git status --porcelain=v1 --untracked-files=all`。已有新提交先比较；未合并继续原分支/PR，已由用户合并则从实际最新 main 接续，不向已合并旧分支追加。

保留所有修改、未跟踪及被忽略文件、环境文件、照片、二维码和历史证据；仅安全 fast-forward，不 reset、clean、force push、自动合并或改变可见性。Windows 未实际检查不得称已同步。

优先查当前项目和用户提供的 ZIP 所在位置。包不在 WebCodex 可访问的电脑时，只需用户提供下载后路径，不要求重生成或逐张上传。先对六张 PNG 校验，再保留目录结构导入；没有确认目标为空/内容相同前，不执行全目录覆盖。后续提交的是实际图片文件，不是聊天沙箱链接或 Git LFS 指针占位。

### 2. 登记母版并生成运行时图片

实际打开六张图检查地点身份、比例、是否含界面标签、文件完整性。按实际结果填写 recipe 的 `master.path/sha256/width/height/method/reviewed`；`reviewed` 只记录实际素材技术复核，不能据此声称四张新图已获用户最终认可。

来源说明写清“依据聊天原参考、已确认地图与古井风格生成的独立 PNG”。保留旧裁切的来源记录，补充实际生成记录，不伪造与旧裁图逐像素相同的来源链。

继续使用 `node scripts/prepare-a4-art.mjs`，无需第二套资产流水线。旧的“六张 master 都应为空、必然失败”仅适用于未导入状态：改为用独立缺项夹具测试保护，不让它阻止合格母版接入；不删除缺文件、哈希不符及手工文件保护断言。

输出使用 recipe 的六个新路径：`map-restored-v1.webp`、`point-p01-restored-v1.webp` 至 `point-p05-restored-v1.webp`。主图保留原始 PNG 在 assets 下；页面只加载压缩派生图。沿用合理 maxWidth/体积预算，不强拉到旧尺寸，不为了旧矢量图的 79KB 总量压糊，不再调用 village-art.mjs。

### 3. 接入地图、五处详情和折叠列表

地图采用新地图图片完整缩放，按真实 1334:1179 宽高比显示，不使用旧 720:1240 容器、不 cover 裁断、不随 N 拉长底图。不再叠加旧 SVG 绘景/路线或五张重复大图卡；五个可交互 HTML 标签由真实配置和 completedKeys 驱动。

按新地图重新核对锚点：p01 葫芦在左上、p02 祠堂在右上、p03 古井在中左、p04 榕树在右下、p05 眺望平台在左下。以上只是定位方向，最终百分比必须对着实际图片确定；不要沿用旧图坐标。标签和图片共享相对定位容器，窄屏不重叠、不盖关键主体、不超出边界；每个地点独立可点。

地图/列表点击仍只查看，不授予扫码资格；状态按 key，不按完成数量点亮前几个。业务 N 动态；移除配置点同时移除该标签；新增无锚点的地点在已有折叠列表可访问，不借用其他地点的图或位置。

详情与列表沿用唯一 points 配置、PointArt 和稳定 key，替换对应 image/alt/尺寸/焦点；五张详情保持 3:2、无拉伸，列表按需派生缩略图。不把任何插画当实景测绘，不因图片上的装饰纹样改地名。

### 4. 保留已完成业务与最新 UI

保留：首页/地点/成功区隐藏 CQ；领取凭证/已领取记录/工作人员页保留真实 CQ；不删除 userLabel API、组件 key 或用户切换判断。扫一扫/领取入口仍在地图上方，主操作首屏可见；身份加载、失败和授权互斥，地点提示随真实状态变化；列表默认折叠；最后一处完成进入 /#claim，不进入工作人员 /r/。

原生选图、预览、重选、扫码门禁、未知结果锁与连续核对失败保护、用户隔离、两路领取只首次计数均不变。不要恢复“本人”修饰、拍照提示、“扫一扫已就绪”、地点标题装饰框。不得回退整轮 A4 或拷回旧 App.vue。

不改正式域名、p01–p05 绑定、/q/ 路径、二维码内容、数据库、公众号配置或业务范围。普通 UI 图标和已定版二维码 SVG 不属于此次替换范围。

运行 npm run check、npm run build、git diff --check；具备独立 MySQL/Chrome 时运行 npm run test:a4:mysql，显式 TEST_DB_*，不用生产库。素材相关断言应验证新 PNG 来源与实际派生结果，地图断言改为图片与 HTML 热点对齐；不要为换图删除原业务回归。

补 320/390/430px 受影响截图：地图、五处详情、展开列表和必要成功/领取状态。对照六张母版目视检查图片质量、地标映射、热点、主体裁切及首屏按钮。新素材不能复用旧视觉指纹；无需机械重截全部历史图片。若测试入口默认全量截图，可复用现有选择机制，不另搭测试平台。

提交六张 PNG、导入清单、必要 recipe/派生图片/页面/测试/说明修改到原开发分支；不得只提交说明而称图片已入库。回读远端文件及最终 HEAD，确认 GitHub 中真实有图。进度只写 TASKS，并区分“母版已导入”“网页已接入”“页面待复核”“线上未更新”。四张新图不应仍标“缺素材”，但也不能自动写成用户已确认。

本轮不触发 Actions、不部署、不自动转 Ready 或合并，不清库或重生成正式二维码。交付最终分支/HEAD、六图映射与体积、检查结果、可打开的实际页面截图以及未验证项。用户确认页面后，再在明确发布授权下沿用原 Actions→本地中转→服务器更新流程。
